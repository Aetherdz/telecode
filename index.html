02 / CAPABILITIES

Purpose-built, not a remote shell.

A

Named session routing

Browse sessions by title, navigate pages, and switch the active target explicitly.

B

Model selection

Browse providers and models in Telegram, then update the active OpenCode session.

C

File exchange

Route incoming attachments to their captured session and restrict outbound files to approved roots.

D

MCP replies

Local coding-agent clients can use bridge tools to send text, files, and session status.

E

Owner checks

Chat identity is checked before routing; sender identity is checked when Telegram provides it.

F

Local operation

No public webhook or hosted broker. Optional systemd user service starts the listener.

06 / SECURITY MODEL

Keep control
on your machine.

Read the security notes ↗
  • Owner chat is verified before message routing.
  • Credentials live in private runtime config, not in the repository.
  • Outbound files are constrained by allowlisted roots and a deny list.
  • Session identifiers are validated before API calls.
  • A local lock prevents duplicate Telegram listeners.
  • Targeted routing is OpenCode-specific; MCP is not remote shell access.

↳
Guided source install

The installer checks your environment, backs up CLI config before changing it, and keeps private bot settings in your user config directory.

Install in a few steps

  1. 01
    Clone the repository
    git clone https://github.com/Aetherdz/telecode.git
  2. 02
    Run the guided installer
    cd telecode && ./install.sh
  3. 03
    Connect your Telegram chat

    Enter your numeric ID from @Getmyid_bot, or choose automatic detection and send /start to your own bot.

  4. 04
    Restart your CLI

    Restart the selected coding-agent CLI to load MCP, then send /start in Telegram. Check the service with telecode status.

    telecode status
